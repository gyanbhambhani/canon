# Canon v0.4 ("Canon-Py"): design

2026-11-22. Status: **draft**. The rulings below are candidates, to be confirmed or overturned
by the Python-shaped likelihood study (research/v0.4/likelihood). Numbers are added when the
study has run.

## Goal and constraints

Canon v0.4 keeps Canon's semantics and guarantees but changes the surface to a strict subset of
typed Python syntax:

- types on every signature, always checked;
- effects declared in the signature, with undeclared or unused effects a compile error;
- `Result` instead of exceptions;
- exhaustive matching with generated fixes;
- one canonical text per program;
- compiler patches and `--fix`;
- contract fuzzing;
- sealed effects and the capability guard.

The v0.3 measurement (docs/v0.3-proposal.md) found that Canon-Py text is about as surprising to
code models as typed Python, and 14 to 17 nats per program less surprising than Canon's own
syntax on matched algorithms.

Implementation constraint: the new front end parses to the **same AST** as v0.3, so the type
checker, effect checker, code generator and runtime are reused unchanged. As a result, every v0.4
spelling must map onto an existing AST node. Python features with no Canon meaning are rejected
with a diagnostic that names the Canon form; they are not added. These include methods, indexing
lists, `continue`, exceptions, classes with behaviour, and multi-statement `case` bodies.

## Construct table (draft)

| Construct | v0.3 spelling | v0.4 candidate | Open question |
| --- | --- | --- | --- |
| Function | `fn f(x: Int) -> Int { ... }` | `def f(x: int) -> int:` + 4-space indented block | re-test `def` vs `fn` and indent vs braces in Python context |
| Generics | `fn first[T](xs: List[T])` | `def first[T](xs: list[T])` (PEP 695) | none |
| Types | `Int Float Bool String Unit List[T] Map[K, V] (A, B)` | `int float bool str None list[T] dict[K, V] tuple[A, B]` | score; `Option`, `Result`, `Error`, `Json` keep their names |
| Function types | `fn(A) -> B` | `Callable[[A], B]` | score |
| Option | `Option[T]`, `Some(x)`, `None` | same | `T \| None` would hide the `Some` the values need; score anyway |
| Effects | `effects: io, net` clause line | `@effects(io, net)` decorator | score against docstring, comment and return-type forms |
| Contracts | `requires: e` / `ensures: e` lines | `@requires(e)` / `@ensures(e)` decorators, `result` names the return value | score against `assert` at entry plus before return |
| Records | `type Item { sku: String, ... }` | `@dataclass` + `class Item:` with annotated fields | score against plain `class` and `NamedTuple` |
| Record literal | `Item { sku: "a", qty: 1 }` | `Item(sku="a", qty=1)` | none |
| Sum types | `type Op =\n  \| A(x: Int)\n  \| B` | `type Op = A(x: int) \| B` (one line, wrapped in parentheses when long) | not legal Python; score against one dataclass per variant |
| Result propagation | `try e` | `e?` or `try_(e)` | score; `try` is a Python keyword with another meaning |
| match returned or bound | `return match x { P => e, }` | Python `match x:` statement, each `case P:` body one `return e` (or `y = e`, or a call) | multi-statement case bodies have no AST; score block vs one-line cases |
| match on Bool | `match c { true => a, false => b }` | `a if c else b` | score |
| match nested in an expression | allowed since v0.2 | not expressible; S001 asks to bind it first | count how often it occurs |
| Lambdas | `\|x\| x + 1` | `lambda x: x + 1` | score |
| Pipelines | `xs \|> f() \|> g()` (3+ stages) | dropped; nested calls (still parsed, fmt rewrites) | score nested vs pipeline vs named steps |
| Bindings | `let x = e` / `var x = e` / `x = e` | `x = e`; first binding creates, mutability inferred from later assignment | score against `let`/`var` and `Final` |
| Augmented assignment | `x = x + e` | `x += e` | score |
| Mutating parameters | not allowed (T006) | allowed: assigning a parameter rebinds a local copy (value semantics, no caller effect) | score direct vs copy |
| Logical operators | `&&` `\|\|` `!` | `and` `or` `not` (with Python's precedence for `not`) | score in Python context |
| Boolean literals | `true` `false` | `True` `False` | score |
| None tests | `x == None` | `x is None` / `x is not None` | score |
| Membership | `contains(xs, x)` | `x in xs` / `x not in xs` | score |
| Tuple slots | `t.0` | `t[0]` (integer literal only) | score |
| Strings | `"a" + to_string(n)` | f-strings, desugared to `+` and `to_string` | score |
| Integer division | `/` truncates | `/` (unchanged); `//` and `**` rejected with a diagnostic | semantic trap for Python readers; documented |
| Holes | `?` / `?name` | `...` (unnamed); named form to decide | depends on the try spelling |
| assert | `assert(c)` | `assert c` statement | none |
| Tests | `test "name" { ... }` | `def test_name() -> None:` (pytest form) | score against `@test("name")` |
| Test effects | `effects: fs` line after the test name | `@effects(fs)` on the test def | none |
| Empty block | `{}` | `pass` | none |
| else-if | `else if` | `elif` | none |
| Imports | `use std.x` | `import std.x` | none |
| for over pairs | `for (i, x) in xs` | `for i, x in xs:` | none |
| Comments | `#` whole line | `#` whole line | none |
| Layout | 2-space indent, 1 blank line between items | 4-space indent, 2 blank lines (PEP 8 / Black) | score both |

## Compatibility

- The parser still accepts v0.3 brace syntax, and therefore v0.2 and v0. The surface is detected
  per file. `canon fmt --write` migrates an older file to v0.4 mechanically.
- `--v0.3` (the CLI flag, or compiler `features: V03`) keeps v0.3's brace printer, and `--v0.2`
  keeps v0.2's. In those modes the oracle stays byte-exact for every construct those versions
  did not change.
