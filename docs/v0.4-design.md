# Canon v0.4 ("Canon-Py"): design

2026-11-22. Status: rulings made on the 1.5B likelihood study; implementation in progress on this
branch. The 7B scores and the corpus measurements are added when they have run.

## Goal and constraints

Canon v0.4 keeps Canon's semantics and guarantees but changes the surface to a strict subset of
typed Python syntax:

- types on every signature, always checked;
- effects declared in the signature, with undeclared or unused effects a compile error;
- `Result` instead of exceptions;
- exhaustive matching with generated fixes;
- one canonical text per program;
- compiler patches and `--fix`;
- contract fuzzing;
- sealed effects and the capability guard.

The v0.3 measurement (docs/v0.3-proposal.md) found that Canon-Py text is about as surprising to
code models as typed Python, and 14 to 17 nats per program less surprising than Canon's own
syntax on matched algorithms.

**Same AST.** The new front end parses to the AST v0.3 uses, so the type checker, effect checker,
code generator and runtime are reused. Only their diagnostic wording changes.

- Every v0.4 spelling therefore maps onto an existing node.
- Python features that have no Canon meaning are rejected with a diagnostic that names the Canon
  form, and are not added: methods, list indexing, `continue`, `try`/`except`/`raise`, classes
  with behaviour, multi-statement `case` bodies, `//`, `**`, comprehensions and keyword arguments
  to functions.
- This is the main difference from the v0.3 prototype (research/v0.3/canonpy), which kept Python's
  library (indexing, methods, comprehensions) and Python's semantics. v0.4 keeps Canon's library
  and Canon's semantics. The measurements below say what that costs.

## Evidence

research/v0.4/likelihood/REPORT.md. Each construct is spelled several equivalent ways inside three
small programs written in the candidate v0.4 surface, and each program is scored by total
log-probability under a local base model, after the header `# A Canon source file (main.cn).
Canon is a strictly formatted, effect-typed subset of Python.`

- **Delta** is the chosen spelling minus the best alternative, in nats, averaged over the three
  contexts. Positive means the model agrees with the ruling.
- The **1.5B** column is Qwen2.5-Coder-1.5B (fp32). The 7B column is filled in after its single
  run.

## Rulings against the model, or not decided by it

- **Contracts stay decorators (-12.8 nats where used).** The model prefers `assert` at entry and
  an `assert` on a `result` variable before a single `return`.
  - A contract is part of the signature: it is checked on every return, fuzzed by `canon test`,
    skipped by `--no-contracts`, and blamed with R001/R002 rather than R005.
  - An `ensures` written as an assert only covers the one return it precedes.
  - Treating a body's leading asserts as `requires` would silently change existing asserts
    into fuzzed contracts.
  - Contracts appear in about a quarter of Claude's programs, so the expected cost is about
    3 nats per program.
- **Sum types use the compact line (a tie).** With one dataclass per variant, `Circle` would look
  like a type that could appear in a signature, which Canon rejects. The compact line also says
  in one place that the type is closed, which is what makes exhaustiveness checking possible.
- **Pipelines are dropped (a tie).** Python has none, and one fewer construct is one fewer rule
  for the agent to learn.
- **Holes lose their names.** `...` cannot carry a name. A v0.3 `?best` migrates to `...`, and the
  H001 diagnostic still reports the expected type and the candidates.
- **`//` and `**` are rejected, `/` is kept.** Canon's Int `/` truncates toward zero and its `%`
  takes the sign of the dividend (as in C and JavaScript), whereas Python's `/` is float division
  and its `//` and `%` floor.
  - Same AST and runtime means Canon's arithmetic, so a Python reader's expectation is wrong
    for `/` on Ints, and for `%` and division with negative operands.
  - The type checker catches the common case: a float expected from Int `/` gives T001 or T009.
  - `//` is rejected (P001 naming `/`) rather than silently accepted with a different rounding
    rule.
  - This is the largest remaining semantic trap.

## Semantics of the Python-shaped forms

- **Bindings.** `x = e` binds a new name when `x` is not yet visible in the function. Otherwise it
  assigns, and the original binding becomes mutable.
  - Scopes are Canon's: block scoped. A name first bound inside an `if` is not visible after it;
    the type checker says so (T002, with a hint to bind it before the `if`).
  - fmt marks nothing: whether a binding is mutable is a property the compiler infers from the
    text, and every assignment is a `NAME =` or `NAME op=` line, so mutations stay searchable.
  - Migrating v0.3 code:
    - a `let` that shadows a visible name is renamed `name_2` (shadowing has no v0.4 spelling);
    - a `var` that is never assigned becomes immutable;
    - `let p = p` on a parameter is dropped.
- **Parameters.** Assigning to a parameter makes the parser insert a hidden `var p = p` at the top
  of the body, and the printer omits it. The caller is unaffected, because Canon values are
  immutable.
- **match.** Python's statement form maps onto Canon's match expression:
  - every case body is exactly one statement, and all cases have the same shape: all `return e`,
    or all `target = e` with the same target, or all calls;
  - a case whose body is itself such a `match` nests;
  - a match on a Bool with `True`/`False` (or `_`) arms prints as `a if c else b`;
  - a non-Bool match nested inside a larger expression (legal since v0.2) cannot be written in
    v0.4. fmt reports S001 at it, and the agent binds it to a name first.
- **f-strings.** `f"a{x}b"` is `"a" + to_string(x) + "b"`.
  - A `+` chain made only of string literals and `to_string` calls, with at least one of each,
    prints as an f-string; any other `+` stays `+`.
  - `f"{x}"` alone is `to_string(x)`.
  - Format specs (`{x:.2f}`) are rejected.
- **Tests.** `def test_adds_two() -> None:` is the test named "adds two". The name is the
  identifier after `test_`, with underscores read as spaces. v0.3 names that are not plain
  lowercase words are normalized when migrated.
- **Single-quoted strings** are accepted and printed with double quotes (C001 with a patch), not a
  parse error.

## Compatibility

- The parser accepts v0.3 brace syntax (and so v0.2 and v0). The surface is detected per file.
  `canon fmt --write` migrates an older file to v0.4.
- `--v0.3` (the CLI flag, or the compiler option `features: V03`) keeps v0.3's brace printer,
  and `--v0.2` keeps v0.2's. In those modes the oracle stays byte-exact for every construct those
  versions did not change.
