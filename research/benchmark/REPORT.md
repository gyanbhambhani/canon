## Exploratory analysis (after the fact; does not change the verdicts)

These observations were made after seeing the data, so they are hypotheses for a future,
separately pre-registered run, not findings.

**Why C3 failed.** Across the 100 task-model pairs, Canon had fewer distinct programs on 33, the
same on 21 and more on 46. Ignoring identifier names barely changes the averages (Canon 3.48 and 3.16,
TypeScript 3.70 and 3.30), so naming alone does not explain it. Reading the variants shows three sources:

1. **The baseline already removes surface style.** TypeScript is normalized with Prettier, exactly as
   Canon is with `canon fmt`. Canon's canonical form therefore earns no advantage here by design; the
   comparison is about program structure.
2. **Canon's restrictions push models into improvisation.** `match` is only allowed as the whole value
   of `let`, `set` or `return`, and there is no `break`. On tasks that want an early exit from a loop
   (`apply_ops`, `index_of`, `parse_sum`), every run invents its own workaround (a `failed_at` flag, an
   `Option`-returning step function, a helper per case), while TypeScript converges on one early-return
   loop. `apply_ops` with Claude: 10 Canon variants against 1 TypeScript program.
3. **Free choices the grammar cannot fix.** Helper names (`fizz`, `fizz_word`, `fizzbuzz_word`) and
   optional `requires:` contracts multiply otherwise identical programs.

Where a task fits Canon's constructs directly, it converges strongly: `sum_evens` was one identical
program in 10 of 10 Claude runs (TypeScript 2), `factorial` with GPT-6.2 Sol 1 (TypeScript 9),
`join_ints` with Claude 1 (TypeScript 9), and `is_prime` with GPT-6.2 Sol 2 (TypeScript 10).

**The fix loop works as designed.** Every Canon first draft that failed (19 of 500 for Claude, 35 of
500 for GPT-6.2 Sol) failed on canonical form (C001), line length (L001) or, once, pipeline syntax (P005),
never on types, and every one passed after exactly one round of applying the compiler's patch.

**Cost.** Canon runs carry the ~2,800-token reference in every prompt, so tokens per correct program
were about 11 times TypeScript's for Claude and 13 times for GPT-6.2 Sol, and Canon runs took about
1.7 and 1.4 times as long. Claude's total spend: $5.09 Canon, $2.81 TypeScript.

**Hypotheses worth a pre-registered follow-up:** allow `match` in any expression position or add an
early exit from loops (fewer workarounds); make helper decomposition less necessary (fewer names to
choose); and the likelihood study's `while` and bare assignment, which models find far more natural.
