# Canon language reference

Canon is a programming language for AI agents: one way to write every program, effects in every signature, and a compiler that answers with patches. This page is the whole language. Every Canon sample on it passes `canon check`.

## Files and text

Source files end in .cn. Blocks use braces, indentation is two spaces, and statements sit one per line. Comments start with # and take a whole line. Strings use double quotes only. Values, functions, fields and effects are snake_case; types and variants are PascalCase. One line rule matters to the parser: a call's `(` sits on the same line as the function name.

## Types

Built in: Int, Float, Bool, String, Unit, `List[T]`, `Map[K, V]`, `Option[T]`, `Result[T, E]`, tuples `(A, B)`, and function types `fn(A) -> B`. Declare records and sum types like this:

```canon name=types
type Item {
  sku: String,
  qty: Int,
  price: Float,
}

type Step =
  | Call(tool: String, input: String)
  | Answer(text: String)
  | Fail(reason: String)
```

`Option[T]` is `Some(value: T) | None`. `Result[T, E]` is `Ok(value: T) | Err(error: E)`. `Error` is the record `Error { message: String }`. Types may take parameters: `type Box[T] { value: T, }`.

## Functions

Parameter and return types are always written. Optional clauses follow the signature in the fixed order effects, requires, ensures; result names the return value inside ensures. Leaving out effects means pure. The effects are fs, io, net, rand, time, listed exactly and alphabetically. Generic functions name type parameters: `fn first_or[T](xs: List[T], fallback: T) -> T`.

```canon name=helper include=types
fn is_discontinued(item: Item) -> Bool {
  return item.qty < 0
}
```

```canon include=helper
fn restock_cost(items: List[Item], target: Int) -> Float
  requires: target >= 0
  ensures: result >= 0.0
{
  var total = 0.0
  for item in items {
    if item.qty < target and not is_discontinued(item) {
      set total = total + to_float(target - item.qty) * item.price
    }
  }
  return total
}
```

## Statements

let binds an immutable name, var a mutable one, and set assigns to a var, so every mutation is searchable. Locals never carry type annotations. return is always explicit. if / else if / else is the only conditional statement. `for x in xs { }` walks a List and `for cond { }` repeats while true; there is no other loop, and no break or continue. A bare expression statement must be a call (or `try` of a call). `set p.field = v` on a var record rebinds p to an updated copy. A test block is `test "name" { ... }`.

## Expressions

Precedence, loosest first:

| Level | Operators |
|---|---|
| 0 | `\|>` pipeline, lambdas `\|a, b\| expr` |
| 1 | `or` |
| 2 | `and` |
| 3 | `not` |
| 4 | `== != < <= > >=` (never chained) |
| 5 | `+ -` |
| 6 | `* / %` |
| 7 | unary `-`, `try` |
| 8 | calls `f(x)`, fields `a.b`, tuple slots `t.0` |

Only named functions are called; there are no methods and no indexing. Literals: `[1, 2]`, `(a, b)`, `Item { sku: "a", qty: 1, price: 2.5 }`. There is no unit literal: `()` and `Ok(())` do not parse. A lambda body is one expression. `try e` unwraps a Result or returns its error early. match is allowed only as the whole value of let, set or return, with one arm per line. Patterns: `_`, a name, a literal, a variant `Some(x)`, a tuple `(a, b)`, nested.

```canon include=types
fn band(item: Item) -> String {
  let band = match (item.qty > 0, item.price) {
    (false, _) => "out",
    (true, 0.0) => "free",
    _ => "priced",
  }
  return band
}
```

## The pipeline rule

`x |> f(y)` means `f(x, y)`. Whether a chain is written as a pipeline or as nested calls is not a choice: three or more chained calls are a pipeline with one stage per line, and fewer are nested calls. A call whose first argument is a literal, such as `range(0, n)`, can start a pipeline but never becomes a stage.

```canon include=types
fn cheapest(items: List[Item], k: Int) -> List[String] {
  return items
    |> filter(|i| i.qty > 0 and i.price > 0.0)
    |> sort_by(|i| i.price)
    |> take(k)
    |> map(|i| i.sku)
}
```

## Holes

Write `?` or `?name` where you are unsure. The compiler reports the type the hole needs and the functions in scope that return it (H001), then you fill it.

## What fmt collapses

The checker rejects any file fmt would change, and the error carries the patch. All of these collapse to one form: whitespace and blank lines; redundant parentheses; optional commas; `else { if … }` to `else if`; `x == true` to `x` and `x == false` to `not x`; `not not x` to `x`; `007` to `7` and `1.50` to `1.5`; import order and duplicates; effect order; clause order; pipeline versus nested call. Lines are at most 100 characters.

## Runtime

Strict, left to right. Int is a 53-bit safe integer; Float is 64-bit. Int with Int gives Int, Float with Float gives Float; mixing is T009 (wrap the Int in `to_float`). Int division truncates toward zero. `+` is numeric only; join strings with `concat`. `<` and friends work on Int, Float and String; `==` compares any two values of one type by structure, except functions. Values are immutable; lambdas capture values. A lambda with n parameters given one n-tuple unpacks it: `map(pairs, |k, v| ...)`. Map keys are Int, Float or String.

`try e` needs a Result: `Ok(v)` becomes v; `Err(x)` returns `Err(x)` from the enclosing function, which must return a Result with the same error type. No `try` in lambdas or tests. Contracts: requires is checked on entry, ensures on every return.

`canon run file.cn` calls `fn main() -> Unit` (or a main returning a Result, whose Err prints and exits 1). `canon test file.cn` runs every test block; there time starts at 0 and moves only by sleep, rand is seeded with 42, and test blocks need no effects clause. `use std.<name>` is accepted; any other `use` is M001.

## Diagnostics

`canon check --json` prints `{ ok, canonical, diagnostics }`. Each diagnostic has code, severity, message, line, col, and often `fix.diff` (a unified diff: apply it as is) and `data`. Apply patches mechanically; answer holes; rewrite code only for parse and naming errors.

- P001 to P005: parse errors (P002 comment not on its own line, P003 local annotation, P004 bare non-call statement, P005 pipeline stage not a call)
- C001: not canonical form; patch is the whole normalization
- S001: match inside a larger expression
- L001: line over 100 characters; bind a subexpression with let
- N001: naming rule broken
- E100: unknown effect · E101: effect used, not declared (patch) · E102: declared, never used (patch)
- H001: hole, with expected type and candidates
- T001 mismatch · T002 unknown name · T003 wrong argument count · T004 non-exhaustive match (patch adds arms with holes) · T005 missing return · T006 set on a let or parameter · T007 try outside a matching Result function · T008 unknown field · T009 mixed Int and Float (patch)
- M001: a `use` other than `use std.<name>`

## Runtime traps

A trap stops the program and prints one JSON object: code, message, line, col, and a stack (innermost first).

- R001 requires failed · R002 ensures failed · R003 integer overflow · R004 division by zero · R005 assert failed · R006 effect denied by the host

## CLI

`canon check FILE...`, `canon fmt FILE... [--write]`, `canon run FILE [--deny fs,net] [--no-contracts]`, `canon test FILE...`. Every command takes `--json`. Exit codes: 0 success, 1 diagnostics, failed tests or traps, 2 usage error.
