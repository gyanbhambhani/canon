This page covers statements. Canon has nine: `let`, `var`, assignment `x = e`, `return`, `if`, `for`, `while`, `break`, and a call on its own line.

## let, var and assignment

`let` binds an immutable name. `var` binds a mutable one, and `x = e` assigns to it. Only a `var` can be assigned, so every name that can change is declared with `var`, one search away.

```canon
fn total_qty(qtys: List[Int]) -> Int {
  var total = 0
  for q in qtys {
    total = total + q
  }
  return total
}

test "total" {
  assert(total_qty([1, 2, 3]) == 6)
}
```

Assigning to a `let` binding or to a parameter is T006:

```canon
# expect: T006
fn f() -> Int {
  let x = 1
  x = 2
  return x
}
```

Locals never carry type annotations; types live on signatures. `let x: Int = 1` is P003.

```canon
# expect: P003
fn f() -> Int {
  let x: Int = 1
  return x
}
```

A local may shadow an outer one with a new `let` in an inner block.

## Updating records

Values are immutable. `p.field = v` on a `var` record rebinds `p` to an updated copy; any other name holding the old value still sees it. Nested fields work the same way: `order.address.city = "Oslo"`.

```canon
type Point {
  x: Int,
  y: Int,
}

fn moved(p: Point) -> Point {
  var q = p
  q.x = q.x + 10
  return q
}

test "the caller's copy is unchanged" {
  let a = Point { x: 1, y: 2 }
  let b = moved(a)
  assert(a.x == 1)
  assert(b.x == 11)
}
```

## if, else if, else

`if` is the only conditional statement. The condition must be a Bool (T001 otherwise) and takes no parentheses. Write `else if`, never `else { if … }`: the formatter collapses the second form into the first.

```canon
fn fizzbuzz(n: Int) -> String {
  if n % 15 == 0 {
    return "FizzBuzz"
  } else if n % 3 == 0 {
    return "Fizz"
  } else if n % 5 == 0 {
    return "Buzz"
  }
  return to_string(n)
}

test "fizzbuzz" {
  assert(fizzbuzz(9) == "Fizz")
  assert(fizzbuzz(7) == "7")
}
```

To choose between values rather than statements, use [match](/docs/guide/pattern-matching), which is an expression.

## for and while

There are two loops. `for x in xs { }` walks a List, and `while cond { }` repeats while the condition is true.

```canon
fn collatz_steps(start: Int) -> Int
  requires: start > 0
{
  var n = start
  var steps = 0
  while n != 1 {
    if n % 2 == 0 {
      n = n / 2
    } else {
      n = 3 * n + 1
    }
    steps = steps + 1
  }
  return steps
}

test "collatz" {
  assert(collatz_steps(6) == 8)
}
```

`for x in` takes a List only (a Map is T001). To walk a Map, walk `keys(m)`, `values(m)`, or `zip(keys(m), values(m))`.

## Destructuring in for

When the elements are tuples, the loop names each slot: `for (i, x) in enumerate(xs)`, `for (k, v) in zip(ks, vs)`. Write `_` for a slot you do not need. The names must match the tuple's size (T001 otherwise), and they are plain names, not nested patterns; for those, use `match`.

```canon
fn index_of(xs: List[String], want: String) -> Int {
  for (i, x) in enumerate(xs) {
    if x == want {
      return i
    }
  }
  return -1
}

fn weighted(rows: List[(String, Int, Float)]) -> Float {
  var total = 0.0
  for (_, n, w) in rows {
    total = total + to_float(n) * w
  }
  return total
}

test "destructuring" {
  assert(index_of(["a", "b"], "b") == 1)
  assert(weighted([("a", 2, 0.5), ("b", 1, 1.5)]) == 2.5)
}
```

`for p in enumerate(xs)` with `p.0` and `p.1` is still legal; the formatter cannot turn one form into the other without inventing names.

## break

`break`, alone on its line, leaves the innermost `for` or `while`. `return` leaves the whole function. There is no `continue`: put the rest of the body under an `if`.

```canon
fn first_gap(xs: List[Int]) -> Int {
  var prev = 0
  var gap = -1
  for (i, x) in enumerate(xs) {
    if i > 0 && x - prev > 1 {
      gap = i
      break
    }
    prev = x
  }
  return gap
}

fn count_up(limit: Int) -> Int {
  var i = 0
  while true {
    i = i + 1
    if i >= limit {
      break
    }
  }
  return i
}

test "break" {
  assert(first_gap([1, 2, 4, 5]) == 2)
  assert(count_up(4) == 4)
}
```

`break` outside a loop is T010:

```canon
# expect: T010
fn f(n: Int) -> Int {
  if n > 0 {
    break
  }
  return n
}
```

`break` is a statement only when it stands alone on its line, so it is not a reserved word: `fn f(break: Int)` still checks.

## return

`return` is always explicit; the last expression of a body is not its value. A function whose return type is not `Unit` must return on every path, or the checker reports T005:

```canon
# expect: T005
fn sign(n: Int) -> Int {
  if n > 0 {
    return 1
  }
}
```

## Expression statements

A bare expression on its own line must be a call, such as `print(x)`, a pipeline ending in a call, or `try` of a call. Anything else is P004; bind other values with `let`.

```canon
fn save(path: String, text: String) -> Result[Int, Error]
  effects: fs, io
{
  try write_file(path, text)
  print("saved")
  return Ok(str_len(text))
}
```

```canon
# expect: P004
fn f(a: Int) -> Int {
  a + 1
  return a
}
```
