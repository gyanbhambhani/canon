This page covers the shape of a Canon file: blocks, lines, comments, strings, literals, names and imports. A program is one `.cn` file plus the standard library. The file holds four kinds of top-level item, separated by one blank line: `use` lines, `type` declarations, `fn` declarations and `test` blocks.

```canon
type Point {
  x: Int,
  y: Int,
}

fn manhattan(p: Point) -> Int {
  return abs(p.x) + abs(p.y)
}

test "manhattan distance" {
  assert(manhattan(Point { x: 3, y: -4 }) == 7)
}
```

## Blocks and lines

Blocks use braces. Indentation is two spaces, and statements sit one per line. No rule of the grammar depends on indentation, but the checker accepts only the formatter's layout, so a file indented any other way fails with C001. Its patch is the reformatted file, and `canon check --fix` applies it for you. [Formatting rules](/docs/canonical-form) lists every rule.

A line is at most 100 characters. When a statement runs longer, the formatter breaks its outermost list, tuple, record or call brackets one item per line, each item ending with a comma:

```canon
fn checks(name: String, age: Int, email: String) -> List[(Bool, String)] {
  return [
    (name == "", "name is empty"),
    (age < 0 || age > 150, "age out of range"),
    (email == "", "email is empty"),
  ]
}
```

A long line the formatter cannot break that way (a long condition, say) is L001: bind a subexpression with `let`.

## The line rule for calls

One line break matters to the parser: a call's `(` sits on the same line as the function name. A `(` that starts a line starts a new statement instead, which keeps a parenthesized line from gluing itself onto the line above as a call.

```canon
# expect: P004
fn f(a: Int) -> Int {
  let b = a
  (a)
  return b
}
```

Here `(a)` is read as its own statement, and a statement that is not a call is P004.

## Comments

Comments start with `#` and take a whole line. The formatter moves a comment written at the end of a line onto its own line below. Inside a `match` or a record type, comments are not allowed at all (P002). A comment directly above a top-level item stays attached to it.

```canon
# Areas are in square meters.
fn area(width: Int, height: Int) -> Int {
  # no overflow check needed here: the runtime traps with R003
  return width * height
}
```

## Strings

Strings use double quotes only; single quotes are a parse error (P001). The escapes are `\"`, `\\`, `\n` and `\t`; any other escape is T001. Strings join with `+`.

```canon
test "escapes" {
  let s = "say \"hi\"\n"
  assert(str_len(s) == 9)
  assert("can" + "on" == "canon")
}
```

## Literals

| Kind | Examples |
|---|---|
| Int | `0`, `42`, `-7` (53-bit safe range) |
| Float | `0.0`, `2.5`, `1e-05` |
| Bool | `true`, `false` |
| String | `"text"` |
| List | `[1, 2, 3]`, `[]` |
| Tuple | `(1, "a")` |
| Record | `Point { x: 1, y: 2 }` |
| Variant | `Some(3)`, `None`, `Ok(1)`, `Err(e)` |

The formatter prints every number one way: `007` becomes `7`, `1.50` becomes `1.5`, and `1e3` becomes `1000.0`. There is no unit literal: `()` does not parse.

## Naming

Values, functions, parameters, fields and effect names are `snake_case`. Types and variants are `PascalCase`. A name that breaks the rule is N001.

```canon
# expect: N001
fn getUser(id: Int) -> Int {
  return id
}
```

## Imports

A program is one file plus the standard library, which is always in scope. `use std.<name>` lines are accepted (the formatter sorts them and removes duplicates) but never needed. Any other `use` is M001 ("modules arrive in v1"), and a call through a module path, such as `json.stringify(s)`, is T002.

```canon
use std.list

fn count(xs: List[Int]) -> Int {
  return len(xs)
}
```

```canon
use agent.tools

# expect: M001
fn f() -> Int {
  return 1
}
```

## Keywords

```text
fn type let var if else match for in while return use
effects requires ensures true false test try
and or not set
```

The last line holds older spellings that stay reserved so that old files still parse: the formatter rewrites `and`, `or` and `not` to `&&`, `||` and `!`, and `set x = e` to `x = e`. `break` is a statement only when it stands alone on its line, so it is not reserved and can still name a value. There is no `continue`, `class`, `null` or `import`.
