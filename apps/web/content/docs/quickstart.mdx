This page takes you from nothing to a running Canon program, a compiler error, its fix, and a test run. You need Node 20 or later. Save this as `hello.cn`:

```canon
fn main() -> Unit
  effects: io
{
  print("hello, canon")
}
```

Run it with npx. Nothing to install first:

```bash
npx canon-lang run hello.cn
```

```text
hello, canon
```

## Install the canon command

The npm package `canon-lang` provides the `canon` command:

```bash
npm i -g canon-lang
canon --version
```

The rest of these docs write `canon`. Without the global install, write `npx canon-lang` instead.

## See an error and its patch

Every function lists the side effects it has, such as `io` for printing. Delete the `effects: io` line, so the file reads:

```canon
# expect: E101
fn main() -> Unit {
  print("hello, canon")
}
```

(In these docs, a `# expect: CODE` line marks an example that must fail with that code. It is not part of your file.)

```bash
canon check hello.cn
```

```text
hello.cn:1:4: error E101: fn main uses effects it does not declare: io (via print)
  --- a/hello.cn
  +++ b/hello.cn
  @@ -1,3 +1,5 @@
  -fn main() -> Unit {
  +fn main() -> Unit
  +  effects: io
  +{
     print("hello, canon")
   }
hello.cn: 1 problem
```

The error has a stable code (E101), a position (line 1, column 4) and a patch: a unified diff that fixes it. The exit status is 1.

## Let the compiler apply it

A missing effect is a mechanical error: there is exactly one right fix. `canon check --fix` applies every such patch, re-checking after each, and `--write` saves the result:

```bash
canon check --fix --write hello.cn
canon run hello.cn
```

```text
hello.cn: applied E101
hello.cn: ok
hello, canon
```

`--fix` handles layout (C001), effect lists (E101, E102) and mixed Int and Float arithmetic (T009). Everything else needs a decision, so it is reported, not applied.

## An error that needs judgment

Save this as `label.cn`:

```canon
# expect: T001
fn label(n: Int) -> String {
  return "n = " + n
}
```

`canon check --fix label.cn` changes nothing and reports the type error (T001, exit 1). In JSON, the error carries a ranked list of candidate fixes in `data.suggestions`, each with its own patch:

```bash
canon check --json label.cn
```

```json
{
  "ok": false,
  "canonical": true,
  "diagnostics": [
    {
      "code": "T001",
      "severity": "error",
      "message": "type mismatch in operands of +: expected String, found Int",
      "line": 2,
      "col": 10,
      "data": {
        "suggestions": [
          {
            "label": "to_string(n)",
            "diff": "--- a/label.cn\n+++ b/label.cn\n@@ -1,3 +1,3 @@\n fn label(n: Int) -> String {\n-  return \"n = \" + n\n+  return \"n = \" + to_string(n)\n }\n"
          }
        ]
      }
    }
  ]
}
```

Pick the candidate that matches what you meant and apply its diff, by hand or with `patch -p1`:

```bash
canon check --json label.cn | jq -r '.diagnostics[0].data.suggestions[0].diff' | patch -p1
canon check label.cn
```

```text
patching file label.cn
label.cn: ok
```

## Formatting and tests

Canon accepts one layout per program. Save this as `double.cn`:

```canon
# expect: C001
fn double(n:Int)->Int{return (n*2)}

test "double" {
  assert(double(21) == 42)
}
```

`canon check --fix --write double.cn` (or `canon fmt --write double.cn`) rewrites it into the one standard layout:

```canon
fn double(n: Int) -> Int {
  return n * 2
}

test "double" {
  assert(double(21) == 42)
}
```

`canon test double.cn` runs its `test` blocks:

```text
PASS double
1 passed, 0 failed
```

`canon test` also calls every pure function that has a `requires` or `ensures` contract on generated inputs; see [Functions and side effects](/docs/guide/functions-effects-contracts#contract-fuzzing).

## Build from source

To work on Canon itself, clone the repository. You need pnpm.

```bash
git clone https://github.com/gyanbhambhani/canon
cd canon
pnpm install
pnpm build
node packages/cli/dist/index.js run examples/hello.cn
```

The `examples/` folder holds small programs that each pass `check` and run.
