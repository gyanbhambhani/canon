This page lists every rule the formatter applies. The formatter turns any spacing or layout of a program into one standard text, called the canonical form, and Canon accepts only that text. This file fails:

```canon
# expect: C001
fn f()->Int{return 1}
```

`canon check` reports C001 with a patch, a unified diff that rewrites the file into its canonical form:

```text
messy.cn:1:1: error C001: source is not in canonical form; apply the patch (Canon accepts exactly one text per program)
  --- a/messy.cn
  +++ b/messy.cn
  @@ -1 +1,3 @@
  -fn f()->Int{return 1}
  +fn f() -> Int {
  +  return 1
  +}
```

`canon fmt FILE` prints the canonical text; `canon fmt --write FILE` rewrites the file. One patch applies every rule below at once.

## How it works

The parser is loose, so every spacing and layout of a program parses to the same tree. The formatter rewrites forms that mean the same thing (`x == true` and `x`) into one, then prints the tree. A file is accepted only if it equals that printed text.

## The rules

| Rule | Before | After |
|---|---|---|
| Two spaces per level; spaces around binary operators and `->`, after commas and colons | `fn add(a:Int,b:Int)->Int{return a+b}` | `fn add(a: Int, b: Int) -> Int {` … |
| One statement per line; one blank line between top-level items, none inside a block | | |
| An empty body is `{}` | `{` newline `}` | `{}` |
| Redundant parentheses are removed | `((a + 1)) * 2 > (3)` | `(a + 1) * 2 > 3` |
| No trailing comma in arguments, lists, tuples and parameters | `[a, 2, 3,]` | `[a, 2, 3]` |
| Record fields and match arms: one per line, each ending with a comma | `type Point { x: Int y: Int }` | one field per line |
| Sum type variants: one per line, starting with `\|` | `type Light = Red \| Green` | one variant per line |
| `else { if … }` alone in the block becomes `else if` | | `} else if n < 0 {` |
| Bool comparisons and double negation collapse | `x == true`, `x == false`, `not not x` | `x`, `not x`, `x` |
| Numbers print one way | `007`, `1.50`, `1e3` | `7`, `1.5`, `1000.0` |
| `use` lines move to the top, sorted, without duplicates | | |
| Effect names sorted, without duplicates | `effects: time, io, io` | `effects: io, time` |
| Clauses in the order `effects`, `requires`, `ensures`; two `requires` (or `ensures`) lines merge with `&&` | | |
| Three or more chained calls form a pipeline, one stage per line; fewer are nested calls | | see [Pipelines](/docs/guide/pipelines) |
| An end-of-line comment moves to its own line below; a comment above a top-level item stays attached | `let m = n * 2 # cheap` | comment on the next line |
| Arguments inside a call's parentheses join onto one line | `max(a,` newline `0)` | `max(a, 0)` |

## Declarations with clauses

A function's `effects` clause lists the side effects it has; `requires` and `ensures` are its contracts. Each clause sits on its own indented line, and the opening brace moves to a line by itself.

```canon
# expect: C001
fn take_some(xs: List[Int], n: Int) -> List[Int]
  ensures: len(result) <= n
  requires: n >= 0
  requires: n <= 100
{
  return take(xs, n)
}
```

```canon
fn take_some(xs: List[Int], n: Int) -> List[Int]
  requires: n >= 0 && n <= 100
  ensures: len(result) <= n
{
  return take(xs, n)
}
```

## The line rule for a call's parenthesis

A call's `(` must sit on the same line as the function name. A `(` at the start of a line starts a new statement, which is a different program, and the checker rejects it with P004 (a statement that is not a call):

```canon
# expect: P004
fn f(a: Int) -> Int {
  let b = max
  (a, 0)
  return b
}
```

## Line length

A line is at most 100 characters. When a statement is longer, the formatter breaks its outermost brackets (a list, a tuple, a record literal or a call's arguments) one item per line, each with a trailing comma; the rule depends only on the program, so there is still one text. A line it cannot break this way (a long condition, say) is L001: bind a subexpression with `let`. `canon fmt --no-wrap` turns the breaking off (v0.2 behaviour).

```canon
# expect: L001
fn f() -> String {
  return "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" + "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb" + "cccccccccccccccccccccc"
}
```

```canon
fn f() -> String {
  let head = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" + "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"
  return head + "cccccccccccccccccccccc"
}
```

## Old v0 spellings

v0.2 changed three spellings and v0.3 one more. The formatter rewrites the old forms, so an old file fails only with C001, and its patch migrates it: `set x = e` becomes `x = e`, `for cond { }` becomes `while cond { }`, `concat(a, b, c)` becomes `a + b + c`, and (v0.3) `a and not b or c` becomes `a && !b || c`. `!` binds like unary minus, so `not a == b` becomes `!(a == b)`. A v0.2 test block that reads files or calls the network also needs an `effects:` line; `canon check --fix --write` adds it.

```canon
# expect: C001
fn greet(name: String, n: Int) -> String {
  var out = concat("hello ", name)
  set out = concat(out, " #", to_string(n))
  return out
}
```

```canon
fn greet(name: String, n: Int) -> String {
  var out = "hello " + name
  out = out + " #" + to_string(n)
  return out
}
```
