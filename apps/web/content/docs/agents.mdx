This page sets up a coding agent to write Canon: give it the reference, give it the loop, and know what the compiler sends back. The loop is one command, repeated until the file is clean:

```bash
canon check --fix --write --json app.cn
```

`--fix` applies every mechanical patch itself (layout, effect lists, Int and Float conversions), re-checking after each, and `--write` saves the result. What comes back is only what needs the agent's judgment.

## 1. Give the agent the reference

The whole language fits on one page. It is the [Agent reference](/docs/for-agents), served as plain text at:

```text
https://canon-lake.vercel.app/llms.txt
```

If your agent can fetch URLs, point it there. If not, paste the text into its instructions. Every example in it passes `canon check`. Agents have learned Canon from this page alone in the benchmarks; [Research](/research) has the data.

## 2. Give the agent the loop

Put this in the instruction file your agent reads at the start of a session: `CLAUDE.md` for Claude Code, `AGENTS.md` for Codex and other tools that read it, or a project rule in Cursor.

```markdown
## Canon

This project is written in Canon (.cn files). Before writing Canon, read the
language reference at https://canon-lake.vercel.app/llms.txt.

After every change to a .cn file:
1. Run `canon check --fix --write --json FILE`. It applies every mechanical
   fix itself and reports only the problems that need you.
2. For T001 with `data.suggestions`, apply the candidate `diff` that matches
   what you meant (`patch -p1` applies it from the project root).
3. For H001 (a hole), replace the `?` with a value of type `data.expected`,
   often a call to one of `data.candidates`.
4. For T004, apply `fix.diff` to add the missing match arms, then fill their holes.
5. For any other code, change the code as the message says.
6. Run step 1 again. Repeat until it prints "ok": true.

Then run `canon test FILE`. Never edit a test to make it pass.
```

If `canon` is not installed globally, write `npx canon-lang` in its place.

## 3. Read the JSON

Here is a first draft with three problems: `report` prints without declaring `io`, `mean` mixes Int and Float, and `report` adds a Float to a String.

```canon
# expect: E101
fn mean(xs: List[Int]) -> Float {
  return sum(xs) / len(xs) * 1.0
}

fn report(xs: List[Int]) -> Unit {
  print("mean: " + mean(xs))
}
```

`canon check --fix --write --json app.cn` fixes the first two and returns the third:

```json
{
  "ok": false,
  "canonical": true,
  "diagnostics": [
    {
      "code": "T001",
      "severity": "error",
      "message": "type mismatch in operands of +: expected String, found Float",
      "line": 8,
      "col": 9,
      "data": {
        "suggestions": [
          {
            "label": "to_string(mean(xs))",
            "diff": "--- a/app.cn\n+++ b/app.cn\n@@ -5,5 +5,5 @@\n fn report(xs: List[Int]) -> Unit\n   effects: io\n {\n-  print(\"mean: \" + mean(xs))\n+  print(\"mean: \" + to_string(mean(xs)))\n }\n"
          }
        ]
      }
    }
  ],
  "applied": [
    "E101",
    "T009"
  ],
  "source": "fn mean(xs: List[Int]) -> Float {\n  return to_float(sum(xs) / len(xs)) * 1.0\n}\n\nfn report(xs: List[Int]) -> Unit\n  effects: io\n{\n  print(\"mean: \" + mean(xs))\n}\n"
}
```

| Field | Meaning |
|---|---|
| `ok` | `true` when nothing is left to fix |
| `canonical` | `true` when the text is in the formatter's one standard layout |
| `applied` | The codes `--fix` applied, in order (only with `--fix`) |
| `source` | The fixed text (only with `--fix`; `--write` saves it to the file) |
| `diagnostics[].code` | A stable code such as T001; see [Errors and fixes](/docs/diagnostics) |
| `diagnostics[].message` | One line for people |
| `diagnostics[].line`, `.col` | Position in the fixed text, counting from 1 |
| `diagnostics[].fix.diff` | A mechanical fix as a unified diff (T004 is the only one `--fix` leaves for you) |
| `diagnostics[].data` | Extra facts: `missing`, `unused`, `expected`, `candidates`, `suggestions` |

Two things to know about this output:

- **Positions and diffs refer to the fixed text,** `source`, not to the draft. With `--write` that is the file on disk; without it, apply them to `source`.
- **`--fix` restates; it does not guess.** The T009 patch wrapped the Int side in `to_float`, so `mean` still divides two Ints (truncating) before converting. If you meant a Float mean, write `to_float(sum(xs)) / to_float(len(xs))`. The patch keeps the program's meaning; only you know the intent.

Without `--fix`, `canon check --json` prints the same object without `applied` and `source`, and every mechanical diagnostic carries its own `fix.diff`. Each diff is computed against the file as checked, so after applying one, check again for the next.

## Holes: ask the compiler

A hole is a `?` (or a named `?best`) written where the agent is unsure what expression goes. The compiler reports H001 with the type the hole needs and the functions in the file that return it:

```json
{
  "code": "H001",
  "severity": "error",
  "message": "hole ?best in fn score: needs a value of type Int",
  "line": 6,
  "col": 10,
  "data": {
    "expected": "Int",
    "candidates": [
      "total(xs: List[Int]) -> Int"
    ]
  }
}
```

A file with holes does not run. See [Holes](/docs/guide/holes).

## What the agent's code can do

The checker holds every program to the effects its entry point declares: `canon run` lets the program perform only the effects `main` lists, and `canon test` lets each test perform only `io`, `time` and `rand` (virtual under the test host) plus the `fs` or `net` it declares. A runtime guard enforces the same bound even if the checker were wrong. So reading `main`'s signature tells you the most a checked program can do.

The bound is on the program, not on each function. A function that takes a function as a parameter, such as `fn apply(f: fn(String) -> Unit, s: String) -> Unit`, declares no effects, yet performs `io` when its caller passes `print`; the caller that names `print` must declare `io`. Effects on function types are planned for v0.4.

## Tips for any agent tool

- **Load the reference every session.** Models have not seen Canon in training. Keep the reference in the project instructions, not in a message that scrolls away.
- **Let the agent run commands.** Allow the `canon` command (or `npx canon-lang`) in the tool's permission settings.
- **Prefer `--json`.** Text output is for people and leaves out `data.suggestions`; the JSON keeps every field and the exact diffs.
- **Apply, do not retype.** A patch fixes the problem and any layout drift together. Retyping by hand can introduce a layout error, which `--fix` then has to undo.
- **Ask with holes.** Tell the agent it may write `?` when unsure and use the H001 answer, rather than guess.
- **Write contracts.** `canon test` fuzzes every pure function that has `requires` or `ensures`, so a contract is a test the agent did not have to write.
