This page lists what Canon does today and what comes next. The current language is v0.3, which reads like this:

```canon
fn halvings(n: Int) -> Int {
  var k = n
  var steps = 0
  while k > 1 {
    k = k / 2
    steps = steps + 1
  }
  return steps
}
```

The full checklist, with every milestone and its tests, is [ROADMAP.md on GitHub](https://github.com/gyanbhambhani/canon/blob/main/ROADMAP.md).

## Shipped

- **The compiler.** Parser, formatter, type checker and code generator, written in TypeScript with no runtime dependencies. It runs in Node and in the browser. Every error has a stable code, and every mechanical fix comes back as a patch (a unified diff).
- **The `canon` command.** `check` (with `--fix`), `fmt`, `run` and `test`, each with `--json` output, published on npm as `canon-lang`.
- **The runtime and standard library.** Programs compile to JavaScript. Effects (files, printing, network, randomness, time) are declared on every function, enforced at run time by a capability guard, and can be denied with `--deny`.
- **The docs, the [playground](/play) and the [Agent reference](/docs/for-agents)**, also served as `/llms.txt`.
- **Two studies.** A study of which spellings language models find most natural, and two benchmarks of agents writing Canon (v0, v0.2) against agents writing TypeScript. Results are on the [Research](/research) page.
- **Language v0.2.** `x = e` assignment, `while` loops, `+` to join strings, and `match` in any expression.
- **Language v0.3.** `canon check --fix`; the formatter breaks long statements; ranked T001 suggestions; contract fuzzing in `canon test`; effect-checked tests, pure contracts and the capability guard; `&&`, `||` and `!`; `break`; `for (i, x) in` destructuring. Every change has a switch for experiments. [Design notes](/docs/design-notes#v03-what-the-evidence-decided) say why.

## Next

1. **Benchmark v0.3.** v0.3 is built but not yet measured. A pre-registered experiment will run it against TypeScript and against v0.3 with single changes switched off, so each change's effect can be told apart.
2. **Test Canon-Py.** Canon's rules written as a strict subset of typed Python scored as natural to models as typed Python, and far more than Canon's syntax ([Design notes](/docs/design-notes#the-surprisal-finding-canon-py)). A cheap pre-registered test comes first; a new front end only if it passes.
3. **Effects on function types.** Today the effect bound is exact for a whole program but not for each higher-order function: `fn apply(f: fn(String) -> Unit, s: String)` declares nothing and prints when given `print`. Writing effects into function types would make every signature exact; it needs effect polymorphism in the checker.
4. **A fuller standard library.** Most of the length gap between Canon and Python programs is missing capability, not syntax: indexing, character tests, string repetition, counting. Each addition costs reference space and needs its own evidence.
5. **A strict grammar.** The formatter's one layout, written in a form that constrained-decoding engines accept, so a model cannot emit a file the formatter would change.

## Later

- **A native backend.** Compile through C, then LLVM, with WebAssembly as a target for running agent-written code in a sandbox.
- **A corpus pipeline.** Have models translate tested open-source functions into Canon, and keep only translations that pass the original tests.
- **Memory model.** Every value behaves as its own copy; the compiler removes the copies. No lifetime annotations.
- **Content-addressed compilation.** Identify each function by a hash of its formatted text, so an unchanged function is never recompiled or retested.
- **Modules, a package manager and an editor language server.** Today a program is one file plus the standard library.

## Open questions

- **Concurrency.** Structured spawn blocks behind their own declared effect, or actors in the Erlang style. Either must keep runs replayable. Canon has no concurrency today.
- **Generics depth.** Canon has type parameters but no interfaces. Interfaces risk bringing back many ways to write one thing.
- **Foreign calls.** Calls into C or Rust libraries need an explicit boundary with its own declared effect.
- **The pipeline threshold.** Three chained calls become a pipeline. Whether two or four reads better is untested.
- **Convergence.** Whether a small, strict language makes separate agent runs write the same program is a hypothesis. So far the data does not support it; see [Research](/research) and [Design notes](/docs/design-notes).
