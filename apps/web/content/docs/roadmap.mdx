This page lists what Canon does today and what comes next. The current language is v0.5, which reads like this (in its default brace syntax):

```canon
fn halvings(n: Int) -> Int {
  var k = n
  var steps = 0
  while k > 1 {
    k = k / 2
    steps = steps + 1
  }
  return steps
}
```

The full checklist, with every milestone and its tests, is [ROADMAP.md on GitHub](https://github.com/gyanbhambhani/canon/blob/main/ROADMAP.md).

## Shipped

- **The compiler.** Parser, formatter, type checker and code generator, written in TypeScript with no runtime dependencies. It runs in Node and in the browser. Every error has a stable code, and every mechanical fix comes back as a patch (a unified diff).
- **The `canon` command.** `check` (with `--fix`), `fmt`, `run`, `test` and `build`, each with `--json` output and `--watch`, published on npm as `canon-lang`.
- **The runtime and standard library.** Programs compile to JavaScript. Effects (files, printing, network, randomness, time) are declared on every function, enforced at run time by a capability guard, and can be denied with `--deny`.
- **The docs, the [playground](/play) and the [Agent reference](/docs/for-agents)**, also served as `/llms.txt`.
- **Two studies.** A study of which spellings language models find most natural, and two benchmarks of agents writing Canon (v0, v0.2) against agents writing TypeScript. Results are on the [Research](/research) page.
- **Language v0.2.** `x = e` assignment, `while` loops, `+` to join strings, and `match` in any expression.
- **Language v0.3.** `canon check --fix`; the formatter breaks long statements; ranked T001 suggestions; contract fuzzing in `canon test`; effect-checked tests, pure contracts and the capability guard; `&&`, `||` and `!`; `break`; `for (i, x) in` destructuring. Every change has a switch for experiments. [Design notes](/docs/design-notes#v03-what-the-evidence-decided) say why.

- **Language v0.4.** Effects on function types (`fn(String) -> Unit effects: io`, T011), so every function's own signature bounds what it can do. [Canon-Py](/docs/guide/canon-py), an opt-in Python-shaped syntax for the same language, with its own [agent reference](/docs/for-agents-py). `canon build` (a standalone JavaScript file, or an ES module) and `--watch`. [Design notes](/docs/design-notes#v04-what-building-canon-py-showed) say what the measurements showed.

- **Language v0.5, full-stack.** Project modules with named imports; `api fn` endpoints with routes, typed inputs and outputs and typed errors; validation written once as `requires`, enforced on the server and checked in the client; tables with `store(table)` effects and `net(host)` effects. `canon build` generates a FastAPI backend and a dependency-free TypeScript client that read as hand-written, `canon manifest` lists every endpoint with its effects, and generated files are read-only (G001). See the [full-stack quickstart](/docs/fullstack/quickstart) and the [changelog](/changelog). The experiments on it are in [Research](/research): most results are at the ceiling for frontier models, and the small local model loses at writing Canon.

## Next

1. **The frontier reruns.** CanonBench, Experiment FS-1 and Experiment VA-1 ran out of API credit for Claude Opus 5.5 and GPT-6.2 Sol before finishing. Their reports say exactly which cells are missing and how to resume.
2. **Validation under Unicode and independent authors.** VA-1 found that careful hand-written clients agree with their servers on ASCII-edge inputs; JavaScript and Python are known to differ on characters such as NEL and U+001C, and the references were written from one template. Both are untested.
3. **Experiment 1.** Agents with and without Canon's compiler loop on the hard tasks, against Python and TypeScript, and Canon in both syntaxes, each with its own reference. It also measures v0.3's changes, which have not been benchmarked. Canon-Py becomes the default only if it is at least as correct as brace syntax at lower cost.
4. **Effect polymorphism.** Higher-order standard library functions (`map`, `filter`, ...) take only pure functions today, so an effect per item needs a `for` loop. Letting them pass a function's effects through would need effect variables in the checker.
5. **A fuller standard library.** Most of the length gap between Canon and Python programs is missing capability, not syntax: indexing, character tests, string repetition, counting. Each addition costs reference space and needs its own evidence.
6. **A strict grammar.** The formatter's one layout, written in a form that constrained-decoding engines accept, so a model cannot emit a file the formatter would change.

## Later

- **A native backend.** Compile through C, then LLVM, with WebAssembly as a target for running agent-written code in a sandbox.
- **A corpus pipeline.** Have models translate tested open-source functions into Canon, and keep only translations that pass the original tests.
- **Memory model.** Every value behaves as its own copy; the compiler removes the copies. No lifetime annotations.
- **Content-addressed compilation.** Identify each function by a hash of its formatted text, so an unchanged function is never recompiled or retested.
- **Modules, a package manager and an editor language server.** Today a program is one file plus the standard library.

## Open questions

- **Concurrency.** Structured spawn blocks behind their own declared effect, or actors in the Erlang style. Either must keep runs replayable. Canon has no concurrency today.
- **Generics depth.** Canon has type parameters but no interfaces. Interfaces risk bringing back many ways to write one thing.
- **Foreign calls.** Calls into C or Rust libraries need an explicit boundary with its own declared effect.
- **The pipeline threshold.** Three chained calls become a pipeline. Whether two or four reads better is untested.
- **Convergence.** Whether a small, strict language makes separate agent runs write the same program is a hypothesis. So far the data does not support it; see [Research](/research) and [Design notes](/docs/design-notes).
