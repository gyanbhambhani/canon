This page lists every `canon` command, flag and exit code, with output produced by running the CLI. Install the command with `npm i -g canon-lang`, or run it without installing as `npx canon-lang`. `canon --help` prints:

```text
canon 0.5.0: a programming language for AI agents

usage:
  canon check FILE... [--fix [--write]]
                                 check files; print diagnostics (with patches)
  canon fmt FILE... [--write]    print the canonical form, or rewrite files in place
  canon run FILE [--deny EFFECTS] [--no-contracts]
                                 check, then run fn main()
  canon test FILE...             run the test blocks (deterministic time and rand),
                                 then fuzz every pure function that has a contract
  canon build FILE [-o OUT] [--module] [--deny EFFECTS] [--no-contracts]
                                 check, then write a standalone JavaScript file that
                                 runs with plain node (default OUT: FILE.js; with
                                 --module, an ES module exporting fns: FILE.mjs)

options:
  --json                         machine-readable output (every command)
  --watch                        rerun on every save of FILE until Ctrl-C (check, test, run, build)
  --fix                          apply every mechanical patch (C001, E101, E102, T009) until
                                 none is left; report only what needs judgment (check)
  --write                        with fmt or check --fix: rewrite the files
  --deny fs,net                  make calls to those effects trap with R006 (run, build)
  --no-contracts                 skip requires/ensures checks (run, build)
  --syntax brace|py              the surface fmt prints and diagnostics use (default: brace);
                                 both surfaces are always read, so fmt converts either way
  --help, --version

language versions and switches (for experiments):
  --v0.3, --v0.2                 the v0.3 or v0.2 language
  --no-wrap --no-break --no-destructure --no-symbols --no-sealed-effects --no-suggestions
  --no-fn-effects                each turns one v0.3 or v0.4 change off
  --no-capability-guard (run, test, build)    --no-contract-fuzz (test)

exit codes: 0 success, 1 diagnostics / failed tests / traps, 2 usage error
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success: no diagnostics (after `--fix`, if given), all tests and fuzz checks passed, the program finished, or the build was written |
| 1 | Diagnostics, a failed test or fuzz check, a runtime trap, or an `Err` returned from `main` |
| 2 | Usage error: unknown command, unknown or misplaced flag, unknown effect in `--deny`, an unknown `--syntax`, `--write` on `check` without `--fix`, `-o` without a file, missing or unreadable file, or more than one file given to `run`, `build` or `--watch` |

A usage error prints `canon: ` and the problem on stderr, then the usage text:

```text
canon: --write needs --fix (canon check --fix --write)
```

With `--watch`, a run that is stopped with Ctrl-C exits 130.

## canon check

```bash
canon check FILE...
canon check --json FILE...
canon check --fix [--write] [--json] FILE...
```

Runs every check: layout (C001), line length, naming, effects, modules, types and holes. Exits 1 if any file has a diagnostic.

Text output prints one line per diagnostic as `path:line:col: severity CODE: message`, then the patch indented by two spaces when there is one, then a summary line per file: `hello.cn: 1 problem`, or `hello.cn: ok` for a clean file. For H001, the candidates follow the message under `candidates:`. T001 suggestions follow under `did you mean (patches in --json):`, one per line, most likely first; their patches appear only in JSON.

`--json` prints `{ ok, canonical, diagnostics }` for one file, where `canonical` says whether the file is already in the formatter's layout. Given several files, it prints an array of such objects, each with a `path` field. [Errors and fixes](/docs/diagnostics) describes the fields. Patch paths are `a/` and `b/` plus the path as given, so `patch -p1` applies them from the same directory.

### --fix

`canon check --fix` is the self-healing loop. It applies the patches of C001 (layout), E101 and E102 (effect lists) and T009 (Int and Float mixed), one at a time with a re-check after each, until none is left, and reports only what needs judgment. It never applies T004 (its patch inserts holes), T001 suggestions or T011 (each is a choice). Without `--write` nothing is saved. Here is a draft with a layout problem, a missing effect and mixed arithmetic:

```text
draft.cn: applied C001, E101, T009 (not written; add --write)
draft.cn: ok
```

With a problem left over, the remaining diagnostics follow the `applied` line, and the exit status is 1:

```text
fixme.cn: applied C001, E101, T009 (not written; add --write)
fixme.cn:6:10: error T001: type mismatch in operands of +: expected String, found Int
fixme.cn: 1 problem
```

With `--json`, the object gains `applied` (the codes, in order) and `source` (the fixed text). Positions and diffs in the remaining diagnostics refer to `source`, which is the file on disk only with `--write`. [Use Canon with your agent](/docs/agents#3-read-the-json) shows a full example.

## canon fmt

```bash
canon fmt FILE...
canon fmt --write FILE...
canon fmt --json FILE...
canon fmt --syntax py --write FILE...
```

Prints each file in the formatter's layout (see [Formatting rules](/docs/canonical-form)). With `--write`, it rewrites each file whose text changes and prints nothing. `fmt` exits 0 even when a file changed; use `check` to fail on that. `fmt` is also how a v0 or v0.2 file migrates to the current language, and how a file moves between brace syntax and [Canon-Py](/docs/guide/canon-py): `--syntax py` prints Canon-Py, and the default prints braces.

`--json` prints `{ path, changed, formatted }` per file (an array for several):

```json
{
  "path": "wrap.cn",
  "changed": true,
  "formatted": "fn checks(name: String, age: Int, email: String) -> List[(Bool, String)] {\n  return [\n    (name == \"\", \"name is empty\"),\n    (age < 0 || age > 150, \"age out of range\"),\n    (email == \"\", \"email is empty\"),\n  ]\n}\n"
}
```

`fmt` needs a file that parses. A parse error goes to stderr with exit 1; in JSON it is `{ path, error }`. `fmt` does not check names, effects or types, so a formatted file can still fail `check`.

## canon run

```bash
canon run FILE
canon run FILE --deny net,fs
canon run FILE --no-contracts
canon run --json FILE
```

Checks the file, compiles it to JavaScript, and calls `fn main()`. `run` takes exactly one file.

- A file with any diagnostic does not run: diagnostics go to stderr, exit 1.
- A file with no `main` prints `error: no fn main() -> Unit in this file`, exit 1.
- `print` output goes to stdout.
- A runtime trap prints one JSON line on stderr, exit 1:

```json
{"code":"R005","message":"assert failed","line":5,"col":3,"stack":[{"fn":"main","line":5,"col":3}]}
```

- An `Err` returned from `main` prints `error: ` and its message on stderr, exit 1.

### --deny EFFECTS

A comma-separated list of effects. Any call to a built-in with a denied effect stops the program with R006, for example `{"code":"R006","message":"effect net denied by the host (http_get)",...}`. An unknown effect name is a usage error.

### The capability guard and --no-capability-guard

By default the host performs only the effects `main` declares; anything else stops the program with R006, naming `fn main`. The checker already guarantees this bound, so on a checked program the guard never fires; it holds the bound even if the checker has a bug. Since v0.4 every function's own signature bounds it too, because function types carry effects (see [What the guarantee covers](/docs/guide/functions-effects-contracts#what-the-guarantee-covers)). `--no-capability-guard` turns the guard off, for experiments.

### --no-contracts

Skips every `requires` and `ensures` check, so R001 and R002 cannot occur.

### --json

Captures stdout and prints one object when the program ends:

```json
{
  "ok": true,
  "status": 0,
  "stdout": "hello, canon\n"
}
```

A trap adds `trap` (the trap object); an `Err` from `main` adds `error`. A file with diagnostics prints `{ ok: false, diagnostics }` instead.

## canon test

```bash
canon test FILE...
canon test --json FILE...
canon test --no-contract-fuzz FILE...
```

Checks each file, runs every `test` block, then fuzzes contracts. Text output is one line per test, with the trap JSON indented under a failure, then a summary. A file with diagnostics prints them on stderr and is counted in the summary (`1 file with errors`), without running its tests. Exit 1 if anything failed.

**The test host.** The clock starts at 0 ms and advances only through `sleep`; `random` and `random_int` use a fixed seed; `print` output is passed through. So `io`, `time` and `rand` are deterministic, and a test uses them without declaring them. Files and the network are real: a test may use them only if it declares them (`effects: fs` on the line after its name), and the capability guard stops any other effect.

**Contract fuzzing.** Every pure, non-generic function with a `requires` or `ensures` clause is called on 200 inputs generated from its parameter types, from a seeded generator, so every run is the same. Inputs that fail the function's own `requires` are discarded; any other trap is a failure that shows the input. During fuzzing the guard allows no effects at all.

```text
PASS abs_diff of equal numbers
FAIL fuzz abs_diff: a = -19, b = 12
  {"code":"R002","message":"ensures failed in fn abs_diff","line":2,"col":12,"stack":[{"fn":"abs_diff","line":2,"col":12}]}
PASS fuzz halve (107 inputs)
SKIP fuzz apply_twice (a function-typed parameter)
2 passed, 1 failed, 1 skipped
```

`PASS fuzz NAME (N inputs)` counts the inputs that ran. A function with a contract that cannot be fuzzed is reported as `SKIP` with the reason: a generic, effectful or parameterless function, a parameter type with no generator, or a `requires` that rejected every generated input (nothing was checked, so it is not a pass). Skips are not counted as passed or failed; the summary counts them. The program is on [Functions and side effects](/docs/guide/functions-effects-contracts#contract-fuzzing).

`--json` prints `{ ok, passed, failed, skipped, files_with_errors, tests, stdout }`. Each test is `{ file, name, passed }` plus `trap` when it failed. Each fuzz entry adds `fn`, `runs`, `discarded`, and either `skipped` (the reason) or, on failure, `counterexample: { args, trap }`:

```json
{
  "file": "fuzz.cn",
  "name": "fuzz abs_diff",
  "fn": "abs_diff",
  "passed": false,
  "runs": 1,
  "discarded": 0,
  "counterexample": {
    "args": [
      "a = -19",
      "b = 12"
    ],
    "trap": {
      "code": "R002",
      "message": "ensures failed in fn abs_diff",
      "line": 2,
      "col": 12,
      "stack": [
        {
          "fn": "abs_diff",
          "line": 2,
          "col": 12
        }
      ]
    }
  }
}
```

`--no-capability-guard` lets tests perform any effect; `--no-contract-fuzz` runs the test blocks only.

## canon build

```bash
canon build FILE
canon build FILE -o OUT
canon build FILE --module
canon build FILE --deny net --no-contracts
canon build --json FILE
```

Checks the file (any diagnostic: printed on stderr, exit 1, nothing written), then writes a standalone JavaScript file that runs with plain `node` and needs no installed packages: the runtime is inlined. The built file prints exactly what `canon run` prints, exits the same way, and writes traps as the same JSON line on stderr. `--deny`, `--no-contracts` and `--no-capability-guard` are baked in only when given at build time. Without `-o`, the output is FILE with `.js`.

```text
$ canon build hello.cn
hello.cn: wrote hello.js
$ node hello.js
hello, canon
```

The output is a CommonJS-compatible script. Inside a package whose `package.json` says `"type": "module"`, name it `.cjs` with `-o`.

`--module` writes an ES module instead (default name FILE with `.mjs`) that exports the program's functions as `fns` and does not run `main`, for embedding Canon code in a JavaScript program:

```js
import { fns } from "./lib.mjs";
console.log(fns.double(21)); // 42
```

`--json` prints `{ ok, out, module, bytes }`, or `{ ok: false, diagnostics }` when the file does not check.

## canon manifest

`canon manifest [FILE]` lists every endpoint (api fn): method, path, function, effects (tables and hosts) and validation rules. It is the permission list to read before the code runs. In a project it needs no file. `--json` gives `{ ok, endpoints, warnings }`, each endpoint with `method`, `path`, `function`, `module`, `effects`, `tables`, `hosts` (`"*"` for any host) and `checks`.

```text
POST /todos                 create_todo     store(todos)   checks: str_len(trim(input.title)) > 0
POST /todos/{id}/complete   complete_todo   store(todos)
GET  /todos                 list_todos      store(todos)   checks: page >= 1 && per_page >= 1 && per_page <= 100
```

An endpoint that declares plain `net` may call any host; the manifest flags it with warning W010.

## Projects

A folder with canon.toml is a project. In it, `canon check`, `canon test` and `canon manifest` need no file: they work on every module under the source folder (`src`, default `canon/`), and `check --fix --write` applies patches in every module. A file inside the source folder is checked with its imports.

## --watch

```bash
canon check --watch FILE
canon check --watch --fix --write FILE
canon test --watch FILE
canon run --watch FILE
canon build --watch FILE
```

Runs the command, then reruns it every time FILE is saved, until Ctrl-C. A watch takes one file (a Canon program is one file). Saves are debounced by about 100 ms, and a save that leaves the text unchanged is ignored, so `check --watch --fix --write` does not retrigger on its own writes. Before each run the screen is cleared (when the output is a terminal), and after it one status line is printed:

```text
[14:03:27] check hello.cn: ok
[14:03:41] check hello.cn: 1 problem
```

`run --watch` runs the program in a child process. A new save stops a run that is still going, even an infinite loop, before starting the next one; its status lines are `started` and `exit N`.

## --syntax

```bash
canon fmt --syntax py --write FILE     # convert to Canon-Py
canon fmt --write FILE                 # convert to brace syntax
canon check --syntax py FILE
```

Picks the surface: `brace` (the default) or `py` ([Canon-Py](/docs/guide/canon-py), the opt-in Python-shaped syntax). The parser reads both surfaces in either mode; the flag decides which one fmt prints, which one `check` accepts as canonical, and how diagnostics, types and patches are spelled. A Canon-Py file checked without `--syntax py` gets C001 with a message that says so. Brace syntax stays the default until Experiment 1 compares the two.

## Language versions and switches

Every v0.3 and v0.4 language change can be turned off on its own, so that an experiment can measure what each one does. They are not meant for everyday use.

| Flag | Commands | Turns off | With it off |
|---|---|---|---|
| `--no-wrap` | all | line breaking by the formatter | long lines stay and are L001 |
| `--no-break` | all | `break` | `break` is a plain name (P004 on its own line) |
| `--no-destructure` | all | `for (a, b) in xs` | a parse error (P001) |
| `--no-symbols` | all | `&&`, `\|\|`, `!` as the canonical form | fmt prints `and`, `or`, `not`; both spellings parse |
| `--no-sealed-effects` | all | effect-checked tests, pure contracts (E103) | tests and contracts are unchecked, and the guard does not apply to tests |
| `--no-suggestions` | all | T001 `data.suggestions` | no suggestions |
| `--no-fn-effects` | all | effects on function types (v0.4) | function types carry no effects, and T011 does not exist (v0.3) |
| `--v0.3` | all | v0.4's change | the v0.3 language |
| `--v0.2` | all | every switch above | the v0.2 language |
| `--no-capability-guard` | run, test, build | the run-time guard | the host allows any effect not denied |
| `--no-contract-fuzz` | test | contract fuzzing | only test blocks run |

`--fix` is opt-in, so leaving it out is its own switch. In the compiler API the language switches are the `features` option of `check`, `fmt` and `compileJs` (`packages/compiler/src/features.ts`; `V04`, `V04_PY`, `V03` and `V02` are the presets). With every switch off, the compiler matches v0.2 byte for byte on the conformance corpus.

## --help and --version

`canon --help` (also `-h` or `help`) prints the usage text above. `canon --version` (also `-v`) prints the version. Both exit 0.
