This page lists every `canon` command, flag and exit code. Install the command with `npm i -g canon-lang`, or run it without installing as `npx canon-lang`. `canon --help` prints:

```text
canon 0.1.1: a programming language for AI agents

usage:
  canon check FILE...            check files; print diagnostics (with patches)
  canon fmt FILE... [--write]    print the canonical form, or rewrite files in place
  canon run FILE [--deny EFFECTS] [--no-contracts]
                                 check, then run fn main()
  canon test FILE...             run the test blocks (deterministic time and rand)

options:
  --json                         machine-readable output (every command)
  --deny fs,net                  make calls to those effects trap with R006 (run)
  --no-contracts                 skip requires/ensures checks (run)
  --help, --version

exit codes: 0 success, 1 diagnostics / failed tests / traps, 2 usage error
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success: no diagnostics, all tests passed, or the program finished |
| 1 | Diagnostics, failed tests, a runtime trap, or an `Err` returned from `main` |
| 2 | Usage error: unknown command, unknown or misplaced flag, unknown effect in `--deny`, missing or unreadable file, or more than one file given to `run` |

A usage error prints `canon: ` and the problem on stderr, then the usage text. In this output, "canonical form" means the formatter's one standard layout, and "effects" are the side effects a function declares (`fs`, `io`, `net`, `rand`, `time`).

## canon check

```bash
canon check FILE...
canon check --json FILE...
```

Runs every check: layout (C001), line length, naming, declared side effects, modules, types and holes (`?` placeholders). Exits 1 if any file has a diagnostic.

Text output prints one line per diagnostic as `path:line:col: severity CODE: message`, then the fix as a unified diff (a patch) indented by two spaces when there is one, then a summary line per file such as `hi.cn: 1 problem` ([Quickstart](/docs/quickstart) shows a full example).

A clean file prints `hi.cn: ok`. For H001, the candidates follow the message, one per line under `candidates:`.

`--json` prints `{ ok, canonical, diagnostics }` for one file, where `canonical` says whether the file already has the formatter's one standard layout. Given several files, it prints an array of such objects, each with a `path` field. [Errors and fixes](/docs/diagnostics) describes the fields. Patch paths are `a/` and `b/` plus the path as given, so `patch -p1` applies them from the same directory.

## canon fmt

```bash
canon fmt FILE...
canon fmt --write FILE...
canon fmt --json FILE...
```

Prints each file in the formatter's standard layout (see [Formatting rules](/docs/canonical-form)) on stdout. With `--write`, it rewrites each file whose text changes and prints nothing. `fmt` exits 0 even when a file changed; use `check` to fail on that.

`--json` prints `{ path, changed, formatted }` per file (an array for several files).

`fmt` needs a file that parses. A parse error (P001 to P005) goes to stderr with exit 1; in JSON mode it is `{ path, error }`. `fmt` does not check names, side effects or types, so a formatted file can still fail `check`.

## canon run

```bash
canon run FILE
canon run FILE --deny net,fs
canon run FILE --no-contracts
canon run --json FILE
```

Checks the file, compiles it to JavaScript, and calls `fn main()`. `run` takes exactly one file.

- A file with any diagnostic does not run: diagnostics go to stderr, exit 1.
- A file with no `main` prints `error: no fn main() -> Unit in this file`, exit 1.
- `print` output goes to stdout.
- A runtime trap prints one JSON line on stderr, exit 1:

```json
{"code":"R005","message":"assert failed","line":5,"col":3,"stack":[{"fn":"main","line":5,"col":3}]}
```

- An `Err` returned from `main` prints `error: ` and its message on stderr, exit 1.

### --deny EFFECTS

A comma-separated list of side effects. Any call to a built-in with a denied effect stops the program with a trap (R006). `--deny net,fs` and `--deny=net,fs` both work. An unknown name is a usage error (exit 2).

### --no-contracts

Skips every `requires` and `ensures` check, so R001 and R002 cannot occur.

### --json

Captures the program's stdout and prints one object when it ends:

```json
{
  "ok": true,
  "status": 0,
  "stdout": "hello, canon\n"
}
```

A trap adds `trap`; an `Err` from `main` adds `error`. A file with diagnostics prints `{ ok: false, diagnostics }` instead.

## canon test

```bash
canon test FILE...
canon test --json FILE...
```

Checks each file, then runs every `test` block in it. Text output is one line per test, with the trap JSON indented under a failure, then a summary:

```text
PASS math works
FAIL wrong
  {"code":"R005","message":"assert failed","line":6,"col":3,"stack":[{"fn":"test \"wrong\"","line":6,"col":3}]}
PASS clock
2 passed, 1 failed
```

Exit 1 if any test failed. A file with diagnostics prints them on stderr and exits 1 without running tests.

Under `canon test`, the clock starts at 0 ms and advances only through `sleep`, and `random` and `random_int` use a fixed seed, so every run is reproducible. `print`, files and the network are real.

`--json` prints `{ ok, passed, failed, tests }`, where each test is `{ file, name, passed }` plus `trap` when it failed.

## --help and --version

`canon --help` (also `-h` or `help`) prints the usage text above. `canon --version` (also `-v`) prints the version. Both exit 0.
