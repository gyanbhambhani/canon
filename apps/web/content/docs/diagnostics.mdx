This page lists every error code Canon reports, with an example that triggers each one. Every diagnostic (an error the compiler reports) has a stable code and a position. Wherever the fix is mechanical, it also carries a patch: a unified diff that fixes it without rewriting the file, which `canon check --fix` applies for you. The message is for people; the patch is for the agent.

## The shape of a diagnostic

`canon check --json FILE` prints `{ ok, canonical, diagnostics }`, where `canonical` says whether the file already has the formatter's one standard layout. A missing side effect, exactly as the checker prints it for a file named `greet.cn`:

```json
{
  "ok": false,
  "canonical": true,
  "diagnostics": [
    {
      "code": "E101",
      "severity": "error",
      "message": "fn greet uses effects it does not declare: io (via print)",
      "line": 1,
      "col": 4,
      "fix": {
        "kind": "patch",
        "diff": "--- a/greet.cn\n+++ b/greet.cn\n@@ -1,3 +1,5 @@\n-fn greet(name: String) -> Unit {\n+fn greet(name: String) -> Unit\n+  effects: io\n+{\n   print(name)\n }\n"
      },
      "data": {
        "missing": [
          "io"
        ]
      }
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `code` | Stable code, listed below |
| `severity` | Always `error` |
| `message` | One line for humans |
| `line`, `col` | 1-based position |
| `fix` | Present when the fix is mechanical: `{ kind: "patch", diff }`, a unified diff against the original file |
| `data` | Extra facts for some codes: `missing` (E101), `unused` (E102), `expected` and `candidates` (H001), `suggestions` (T001: candidate patches, `{ label, diff }`, most likely first) |

Patches are computed against the original file, so one patch fixes the reported problem and any formatting drift together. Apply `fix.diff` as is (for example with `patch -p1`), then check again.

## How an agent should react

| Kind | Codes | Action |
|---|---|---|
| Mechanical | C001, E101, E102, T009 | `canon check --fix` applies them; you never see them |
| Patch with holes | T004 | Apply `fix.diff`, then fill the holes it adds |
| Choice | T001 with `data.suggestions` | Pick the candidate that matches your intent and apply its `diff` |
| Question | H001 | Fill the hole with a value of `data.expected`, often one of `data.candidates` |
| Rewrite | P001 to P005, L001, N001, E100, E103, M001, the other T codes | Change the code; the message says what was expected |
| Trap | R000 to R006 | A runtime failure: fix the logic, or the contract it broke |

A parse error (P codes) stops the check at the first problem, because there is no tree to check further. Otherwise every problem in the file is reported in one pass.

## What --fix does

`canon check --fix` applies the patches of C001, E101, E102 and T009 one at a time, re-checking after each, until none is left (at most 32 rounds), then reports what remains. Those four patches only restate what the program already says: its layout, its exact effect list, an explicit `to_float`. It never applies T004 (its patch inserts holes, which are questions) or a T001 suggestion (a choice between meanings). With `--json`, the result adds `applied`, the codes applied in order, and `source`, the fixed text; `--write` saves it. Positions and diffs in the remaining diagnostics refer to that fixed text.

```text
draft.cn: applied C001, E101, T009 (not written; add --write)
draft.cn: ok
```

The exit status is 0 when nothing is left, so a draft whose only problems were mechanical passes. Every first draft that failed in the two benchmarks so far failed only on mechanical codes, which is why this loop exists; [Research](/research) has those runs.

In the examples below, the `# expect:` line is part of the checked file, so it counts in the line numbers.

## Parse errors

### P001

A token the parser did not expect, with a message naming what it expected. Common causes: a chained comparison, single quotes, a missing return type, a unit literal `()`, or a stray token at top level.

```canon
# expect: P001
fn between(a: Int) -> Bool {
  return 1 < a < 3
}
```

```text
example.cn:3:16: error P001: expected end of comparison (comparisons do not chain; use 'and'), found '<'
```

The message still names v0.2's `and`; write `1 < a && a < 3`.

```canon
# expect: P001
fn greet() -> String {
  return 'hi'
}
```

```text
example.cn:3:10: error P001: single-quoted strings do not exist in Canon; use double quotes
```

```canon
# expect: P001
fn answer() {
  return 42
}
```

```text
example.cn:2:13: error P001: expected '->' and a return type (return types are required), found '{'
```

### P002

A comment inside a match or a record type. Comments must sit on their own line between statements or items.

```canon
# expect: P002
fn f(n: Int) -> Int {
  return match n {
    # zero is special
    0 => 1,
    _ => n,
  }
}
```

```text
example.cn:4:5: error P002: comments must sit on their own line between statements
```

### P003

A type annotation on a local binding. Types live on signatures only.

```canon
# expect: P003
fn f() -> Int {
  let x: Int = 1
  return x
}
```

```text
example.cn:3:8: error P003: local bindings never carry type annotations; types live on signatures
```

### P004

An expression statement that is not a call. Bind other values with `let`. A `(` at the start of a line also triggers it, because a call's `(` must be on the function name's line.

```canon
# expect: P004
fn f(a: Int) -> Int {
  a + 1
  return a
}
```

```text
example.cn:3:3: error P004: an expression statement must be a function call; bind other values with let
```

### P005

A pipeline stage that is not a call. Write `|> f()`, even when `f` takes no other arguments.

```canon
# expect: P005
fn f(xs: List[Int]) -> Int {
  return xs |> sum
}
```

```text
example.cn:3:13: error P005: each pipeline stage must be a call, like '|> f()'
```

## Form

### C001

The file is not in canonical form, the one standard layout the formatter prints. The patch applies every rule on the [Formatting rules](/docs/canonical-form) page at once. That includes the older spellings `set x = e`, `for cond { }` and `concat(a, b)` (v0) and `and`, `or`, `not` (v0.2), which still parse and are rewritten to `x = e`, `while cond { }`, `a + b`, `&&`, `||` and `!`. `--fix` applies it.

```canon
# expect: C001
fn f()->Int{return 1}
```

```text
example.cn:2:1: error C001: source is not in canonical form; apply the patch (Canon accepts exactly one text per program)
```

The patch:

```diff
--- a/example.cn
+++ b/example.cn
@@ -1,2 +1,4 @@
 # expect: C001
-fn f()->Int{return 1}
+fn f() -> Int {
+  return 1
+}
```

### S001

In brace syntax, retired: v0 rejected a `match` inside a larger expression, and since v0.2 `match` may appear in any expression position. In [Canon-Py](/docs/guide/canon-py), `match` is a statement, so a match nested inside a larger expression cannot be written. Converting such a program with `canon fmt --syntax py` reports S001 at the match, and the fix is to bind the match to a name first. There is no patch, because moving the match out could change the order of effects:

```text
s001.cn:2:15: error S001: in Canon-Py a match is a statement: return its value or bind it to a name, then use the name
```

### L001

A line longer than 100 characters after formatting. The formatter breaks a long statement at its outermost list, tuple, record or call brackets (reported as C001, with the patch), and breaks a long pipeline stage's arguments the same way, so L001 is left for lines it cannot break: a long chain of operators, or a single argument too long for its own line. There is no patch: bind a subexpression with `let`. (With `--no-wrap` or `--v0.2`, every long line is L001, as in v0.2.)

```canon
# expect: L001
fn f() -> String {
  return "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" + "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb" + "cccccccccccccccccccccc"
}
```

```text
example.cn:3:101: error L001: line is 109 characters (limit 100); bind a subexpression with let
```

### N001

A naming rule broken. Values, functions, parameters, fields and effects are `snake_case`; types and variants are `PascalCase`.

```canon
# expect: N001
fn getUser(id: Int) -> Int {
  return id
}
```

```text
example.cn:2:4: error N001: function 'getUser' must be snake_case
```

## Effects

A function's `effects` clause lists the side effects it uses: `fs`, `io`, `net`, `rand`, `time`. The checker holds it to that list exactly.

### E100

An effect name that is not one of `fs`, `io`, `net`, `rand`, `time`. It usually comes with E101 or E102, whose patch replaces the clause.

```canon
# expect: E100
fn f() -> Unit
  effects: disk
{
  print("x")
}
```

```text
example.cn:2:4: error E100: unknown effect 'disk'; the effects are fs, io, net, rand, time
example.cn:2:4: error E101: fn f uses effects it does not declare: io (via print)
example.cn:2:4: error E102: fn f declares effects it never uses: disk (effect lists are exact)
```

The patch:

```diff
--- a/example.cn
+++ b/example.cn
@@ -1,6 +1,6 @@
 # expect: E100
 fn f() -> Unit
-  effects: disk
+  effects: io
 {
   print("x")
 }
```

### E101

A function or test uses an effect it does not declare: directly, through a function it calls, inside a lambda, by naming an effectful function as a value, or by calling a function value whose type has effects (`f(s)` where `f: fn(String) -> Unit effects: io`). The patch adds it.

```canon
# expect: E101
fn greet(name: String) -> Unit {
  print(name)
}
```

```text
example.cn:2:4: error E101: fn greet uses effects it does not declare: io (via print)
```

The patch:

```diff
--- a/example.cn
+++ b/example.cn
@@ -1,4 +1,6 @@
 # expect: E101
-fn greet(name: String) -> Unit {
+fn greet(name: String) -> Unit
+  effects: io
+{
   print(name)
 }
```

### E102

A function declares an effect it never uses, or a test declares `io`, `time` or `rand` (which tests never declare). Effect lists are exact, so the patch removes it.

```canon
# expect: E102
fn add(a: Int, b: Int) -> Int
  effects: net
{
  return a + b
}
```

```text
example.cn:2:4: error E102: fn add declares effects it never uses: net (effect lists are exact)
```

The patch:

```diff
--- a/example.cn
+++ b/example.cn
@@ -1,6 +1,4 @@
 # expect: E102
-fn add(a: Int, b: Int) -> Int
-  effects: net
-{
+fn add(a: Int, b: Int) -> Int {
   return a + b
 }
```

### E103

A `requires` or `ensures` clause that performs a side effect, directly or through a function. Contracts must be pure: they are skipped under `--no-contracts`, so an effect in one would happen or not depending on a flag. Compute the value in the body instead.

```canon
# expect: E103
fn wait_for(n: Int) -> Int
  requires: now() >= 0
{
  return n
}
```

```text
example.cn:2:4: error E103: the requires clause of fn wait_for performs effects: time (via now); contracts must be pure
```

### E104

A literal URL whose host the function does not declare, when it declares other hosts with `net(<host>)`. The patch adds the host; whether the function should call it is your decision, so `--fix` does not apply it. Plain `net` allows every host.

```canon
# expect: E104
fn charge() -> Result[String, Error]
  effects: net(api.stripe.com)
{
  return http_get("https://api.evil.example/steal")
}
```

```text
example.cn:2:4: error E104: fn charge calls host api.evil.example (via http_get), but declares only net(api.stripe.com); add net(api.evil.example), or declare plain net for any host
```

A computed URL cannot be checked before the program runs. The capability guard checks it instead, and traps with R006 when the host is not one the calling function declares.

### Effects in tests

Test blocks are effect-checked too. `io`, `time` and `rand` need no declaration in a test, because `canon test` makes them deterministic; `fs` and `net` are real, so a test that uses them declares them on the line after its name, and E101 (with its patch) or E102 apply as for functions:

```canon
test "round trip"
  effects: fs
{
  let w = write_file("/tmp/canon-doc.txt", "hi")
  let r = read_file("/tmp/canon-doc.txt")
  assert(r == Ok("hi"))
}
```

## Holes

### H001

A hole (`?` or `?name`). It is a question, not a mistake: the answer names the type the hole needs and the functions in the file that return it. See [Holes](/docs/guide/holes).

```canon
# expect: H001
fn total(xs: List[Int]) -> Int {
  return sum(xs)
}

fn biggest(xs: List[Int]) -> Int {
  return fold(xs, 0, |acc, x| max(acc, x))
}

fn score(xs: List[Int]) -> Int {
  return ?best
}
```

```json
{
  "code": "H001",
  "severity": "error",
  "message": "hole ?best in fn score: needs a value of type Int",
  "line": 11,
  "col": 10,
  "data": {
    "expected": "Int",
    "candidates": [
      "total(xs: List[Int]) -> Int",
      "biggest(xs: List[Int]) -> Int"
    ]
  }
}
```

## Types

### T001

Type mismatch, such as joining a String and an Int with `+` (convert with `to_string`). This is also the code for other type-level rule breaks: a missing or duplicate record field, a duplicate declaration, redefining a built-in type or function name, an Int literal outside the 53-bit range, an unknown string escape, comparing functions, or a Map key that is not Int, Float or String.

```canon
# expect: T001
fn f(n: Int) -> String {
  return "n = " + n
}
```

```text
example.cn:3:10: error T001: type mismatch in operands of +: expected String, found Int
```

Where a conversion is the likely fix, `data.suggestions` lists candidate patches, most likely first. Here, in `canon check --json`:

```json
"data": {
  "suggestions": [
    {
      "label": "to_string(n)",
      "diff": "--- a/example.cn\n+++ b/example.cn\n@@ -1,4 +1,4 @@\n # expect: T001\n fn f(n: Int) -> String {\n-  return \"n = \" + n\n+  return \"n = \" + to_string(n)\n }\n"
    }
  ]
}
```

| Found | Expected | Suggestion |
|---|---|---|
| Int, Float or Bool | String | `to_string(e)` |
| Int | Float | `to_float(e)` |
| Float | Int | `to_int(e)` (truncates) |
| `Option[T]` | T | `unwrap_or(e, ?)`, with a hole for the fallback |
| T | `Option[T]` | `Some(e)` |
| T | `Result[T, E]` | `Ok(e)` |
| T | `List[T]` | `[e]` |

They are choices, not fixes: each changes what the program means, so `--fix` never applies them, and text output does not show them. `--no-suggestions` turns them off.

### T002

Unknown name: a variable, function, type or variant that does not exist. A call through a module path (`json.stringify(s)`, or a method-style `xs.len()`) is also T002, because functions are called by their plain name: in a project, import one with `use module.{name}` (see M003).

```canon
# expect: T002
fn f() -> Int {
  return missing + 1
}
```

```text
example.cn:3:10: error T002: unknown name missing
```

### T003

Wrong number of arguments to a function or variant, or a lambda with the wrong number of parameters.

```canon
# expect: T003
fn f() -> List[Int] {
  return range(1)
}
```

```text
example.cn:3:10: error T003: range takes 2 arguments, got 1
```

### T004

A match that does not cover every case. The patch adds the missing arms with holes as their values, so the patched file reports only H001.

```canon
# expect: T004
type Shape =
  | Circle(radius: Float)
  | Rect(width: Float, height: Float)

fn area(s: Shape) -> Float {
  return match s {
    Circle(r) => 3.14 * r * r,
  }
}
```

```text
example.cn:7:10: error T004: match is not exhaustive; missing: Rect(_, _)
```

The patch:

```diff
--- a/example.cn
+++ b/example.cn
@@ -6,5 +6,6 @@
 fn area(s: Shape) -> Float {
   return match s {
     Circle(r) => 3.14 * r * r,
+    Rect(_, _) => ?,
   }
 }
```

### T005

A function whose return type is not `Unit` can reach its end without a `return`.

```canon
# expect: T005
fn f(n: Int) -> Int {
  if n > 0 {
    return 1
  }
}
```

```text
example.cn:2:4: error T005: fn f returns Int but can reach its end without a return
```

### T006

Assignment (`x = e` or `x.field = e`) to a name that is not a `var`: a `let` binding or a parameter.

```canon
# expect: T006
fn f(n: Int) -> Int {
  n = 2
  return n
}
```

```text
example.cn:3:3: error T006: cannot assign to n, which is not a var; declare it with var to mutate it
```

### T007

`try` used where it cannot work: on a value that is not a Result, in a function that does not return a Result with the same error type, inside a lambda, or in a test block.

```canon
# expect: T007
fn f(p: String) -> Int
  effects: fs
{
  let t = try read_file(p)
  return str_len(t)
}
```

```text
example.cn:5:11: error T007: try needs the enclosing fn f to return a Result
```

### T008

A field or tuple slot the type does not have.

```canon
# expect: T008
type P {
  x: Int,
}

fn f(p: P) -> Int {
  return p.y
}
```

```text
example.cn:7:10: error T008: type P has no field y
```

### T009

Int and Float mixed in one operator. The patch wraps the Int side in `to_float`.

```canon
# expect: T009
fn f(n: Int, x: Float) -> Float {
  return n * x
}
```

```text
example.cn:3:10: error T009: operator * mixes Int and Float; convert the Int side with to_float
```

The patch:

```diff
--- a/example.cn
+++ b/example.cn
@@ -1,4 +1,4 @@
 # expect: T009
 fn f(n: Int, x: Float) -> Float {
-  return n * x
+  return to_float(n) * x
 }
```

### T010

`break` outside a `for` or `while` loop. (With `--no-break`, `break` on its own line is P004 instead, as in v0.2.)

```canon
# expect: T010
fn f(n: Int) -> Int {
  if n > 0 {
    break
  }
  return n
}
```

```text
example.cn:4:5: error T010: break is only allowed inside a for or while loop
```

### T011

An effectful function is used where the expected function type allows no such effects: passed as an argument, stored in a record field or a list, returned, or wrapped in a lambda whose body calls it. Function types carry effects (`fn(String) -> Unit effects: io`), so a pure function type, such as the parameter of `map`, cannot receive `print`. Choose one fix: declare the effects in the receiving function type (and in the signature of the function that calls it), or stop passing the effectful function. There is no patch, because either fix changes a contract. `--no-fn-effects` turns this check off.

```canon
# expect: T011
fn apply(f: fn(String) -> Unit, s: String) -> Unit {
  f(s)
}

fn main() -> Unit
  effects: io
{
  apply(print, "x")
}
```

```text
example.cn:8:9: error T011: print performs io, but it is used where the function type fn(String) -> Unit allows no such effects; declare them in that type, e.g. fn(String) -> Unit effects: io
```

## API functions

An `api fn` is a function with a `route:` clause. These checks keep every endpoint something both generated sides can carry.

### A001

The shape of an api fn: a path parameter that is not an Int or String parameter; a GET or DELETE parameter that is not a scalar (or an Option of one); more than one body parameter, or a body that is not a record; a type that cannot be sent as JSON (a function, a table, `Option[Option[T]]`, a map with non-String keys); an error type that is not a sum type; a field name that cannot exist in Python; a generic api fn. The message names the allowed form.

```canon
type Query {
  text: String,
}

# expect: A001
api fn search(q: Query) -> List[String]
  route: GET "/search"
{
  return [q.text]
}
```

```text
example.cn:6:8: error A001: api fn search: the query parameter q must be Int, Float, Bool, String or an Option of one, not Query; GET has no body
```

### A002

Two endpoints with the same method and path, in one file or across a project. Parameter names do not matter: `/todos/{id}` and `/todos/{todo_id}` are the same route.

### A003

An api fn's `requires` is its request validation. It runs on the server and in the generated client, so it may use only comparisons, arithmetic, `&&`, `||`, `!`, fields, literals and `str_len`, `trim`, `contains`, `len`, `is_email`, `is_some`.

```canon
fn short(s: String) -> Bool {
  return str_len(s) < 20
}

# expect: A003
api fn hello(name: String) -> String
  route: GET "/hello"
  requires: short(name)
{
  return "hi " + name
}
```

### A004

A table used other than as the first argument of `get`, `scan`, `insert`, `save`, `delete`, `next_id` or `count`. Every access to a table goes through those built-ins, so the effect checker sees each one as `store(<table>)`.

## Modules

### M001

A `use` line Canon cannot resolve. Outside a project (a folder with canon.toml), a program is one file plus the standard library, so only `use std.<name>` is allowed. Inside a project, a module import must name what it takes, `use billing.money.{Money}`, and the standard library is never imported with names. (`use` lines always sort to the top, so the `# expect:` comment sits below.)

```canon
use agent.tools

# expect: M001
fn f() -> Int {
  return 1
}
```

```text
example.cn:1:1: error M001: use agent.tools: only std.<name> is available outside a project
```

### M002

An import cycle between modules of a project. Every module on the cycle reports it, on the import that closes it. Move the items both modules need into a third module that both import.

```text
canon/a.cn:1:1: error M002: import cycle: a -> b -> a; move the shared items into a module both can import
```

### M003

A name that does not resolve across modules: an unknown module, a name the module does not define, a variant imported by name (import its type, which brings its variants), or an item of another module used without importing it. The last case carries a patch that adds the name to the import.

```text
canon/shop.cn:4:10: error M003: fn add is defined in module billing.money; import it: use billing.money.{add}
```

### M004

A top-level name (type, variant, function or table) defined in two modules of a project. Names are unique across a project, because the generated TypeScript types and client are one flat namespace.

```text
canon/shop.cn:1:1: error M004: type Money is already defined in module billing.money; top-level names are unique across a project
```

## Generated code

### G001

A generated file (one that starts with Canon's header) whose contents no longer match its hash: it was edited by hand. `canon check` reports it, naming the Canon source to change instead, and `canon build` refuses to overwrite it unless given `--force`, which discards the edit. A file at a path `canon build` writes, but which Canon did not write, is refused the same way.

```text
backend/canon_generated/logic.py:1:1: error G001: backend/canon_generated/logic.py was edited by hand, but it is generated from canon/todos.cn: make the change in the Canon source and run canon build (canon build --force discards the edit)
```

### G002

Something the Python target cannot express yet: an Option of an Option (even an inferred one, like `first` of a `List[Option[Int]]`), `to_string` of a value that is not an Int, Float, String or Bool, `read_line`, `read_file` or `write_file`, or a computed URL in a function that declares several hosts. `canon build` reports it, naming the function, and writes nothing. The program still runs under `canon run`.

```text
canon/todos.cn:3:10: error G002: the Python target cannot express an Option of an Option (or of Unit): the Python target writes Option[T] as T | None, which cannot nest (fn nested)
```

### W010

A warning from `canon manifest`, not from `canon check`: an endpoint that declares plain `net` may call any host. Name the hosts instead, as `net(api.example.com)`.

```text
warning W010: api fn ping may call any host (effects: net); name the hosts it calls, like net(api.example.com)
```

## Runtime traps

A runtime error stops the program and prints one JSON object on stderr, with the code, message, line, col, and a Canon-level stack listing frames innermost first. `canon run` then exits with status 1. Under `canon test` a trap fails that test (or, during contract fuzzing, is the counterexample) and the runner moves on. Each program below passes `canon check`; the JSON under it is what `canon run` prints.

### R001

A `requires` clause failed on entry. The message names the function.

```canon
fn halve(n: Int) -> Int
  requires: n % 2 == 0
{
  return n / 2
}

fn main() -> Unit
  effects: io
{
  print(to_string(halve(3)))
}
```


### R002

An `ensures` clause failed on return.

```canon
fn discount(price: Float, pct: Float) -> Float
  ensures: result >= 0.0
{
  return price - price * pct
}

fn main() -> Unit
  effects: io
{
  print(to_string(discount(10.0, 1.5)))
}
```

```json
{"code":"R002","message":"ensures failed in fn discount","line":2,"col":12,"stack":[{"fn":"discount","line":2,"col":12},{"fn":"main","line":10,"col":19}]}
```

`canon run --no-contracts` skips both R001 and R002 checks.

### R003

```canon
}
```

### R004

### R005

An `assert` failed. In `canon test`, a failed assert fails that test and the runner moves on. `random_int` with `hi <= lo` also traps with R005.

```canon

  effects: io
{

  assert(len(xs) == 4)
  print("unreachable")
}
```

```json
{"code":"R005","message":"assert failed","line":5,"col":3,"stack":[{"fn":"main","line":5,"col":3}]}
```

### R006

An effect denied by the host. `canon run --deny net,fs` makes those calls trap; the browser playground denies `fs` and `net`. The capability guard also denies any effect the entry point does not declare (`main`'s clause; a test's `fs` and `net`; nothing during contract fuzzing), with a message such as `effect fs denied (write_file): fn main does not declare it`. The checker makes that case unreachable, so seeing it means a checker bug. This program, run with `--deny net`:

```canon
fn main() -> Unit
  effects: io, net
{
  let body = match http_get("https://example.com") {
    Ok(text) => text,
    Err(e) => e.message,
  }
  print(body)
}
```

```json
{"code":"R006","message":"effect net denied by the host (http_get)","line":4,"col":20,"stack":[{"fn":"main","line":4,"col":20}]}
```

### R007

`insert` into a table that already has a row with that key. Use `save` to insert or replace.

```json
{"code":"R007","message":"duplicate key 1 in table todos","line":9,"col":3,"stack":[{"fn":"main","line":9,"col":3}]}
```

### R000

Not part of the spec's list: the runtime reports a host stack overflow, such as runaway recursion, as R000 rather than crashing.
